# RULA Angle Lab v1.0｜跨視角頸部與前臂角度研究

## 0. 這個 ZIP 是什麼？
這是**獨立測試工具**，不會更改正式 RULA 系統的 `222.py`，不會產生可宣稱已驗證的 RULA Grand Score，也沒有實作校正後的多視角 3D 重建。本程式比較相同時間、**相同人體側別**在三個鏡頭的 2D 候選角度與初步品質，並與你自行輸入的人工角度比較，作為研究改善實驗。工程品質門檻未經外部驗證。

**與正式程式一致的角度定義（參考現行 `222.py` v11.4）**：
- 前臂：正式 `222.py` 使用 `abs(180 - angle(肩,肘,腕))` 的**屈曲代理角**，不是直接使用肩－肘－腕的肘內角。測試頁會**同時顯示兩種角度**，但統計時必須把人工量測先換成相同定義；不含前臂跨中線／外側工作補正。
- 頸部：`abs(180 - angle(同側髖, 同側肩, 同側耳))`，是投影代理角，非解剖學頸椎前屈真值。
- 相機 Left/Front/Right 是**拍攝位置**；身體側別「左手側／右手側」是**人體本身**。測人體左側時，三個鏡頭一律用 Pose 7/11/13/15/23；測人體右側時一律用 8/12/14/16/24。
- 正面相機的頸部前屈角度不會被當作可靠替代角度；仍可看到它的投影值作為診斷。

## 1. 部署一個全新的 Streamlit App（建議）
1. 在 GitHub **新增一個獨立 repository**（例如 `rula-angle-lab`），**不要覆蓋正式的 `RULA-System-mediapipe`**。
2. 解壓縮，把 ZIP **內層**的 `app.py`、`angle_lab_core.py`、`requirements.txt`、`packages.txt`、`.streamlit/config.toml`、`runtime.txt` 與 `tests/` 上傳到新 repository 根目錄。注意 `.streamlit` 是隱藏資料夾。
3. 進入 [Streamlit Community Cloud](https://share.streamlit.io/) → Create app → 選擇新 repository 的 `main` → **Main file path 填 `app.py`**。
4. 部署後先確認首頁的「RULA Angle Lab」標題與三支影片上傳框；**不要把原正式網站 `222.py` 改為本實驗程式**。
5. 若 Streamlit 前端再出現 `Failed to fetch dynamically imported module`，先用新的 App 網址無痕開啟、強制重載，並檢查 Network 的 JS 錯誤碼；這不是 RULA 查表錯誤。若安裝失敗，先看最新 Logs 的完整 traceback。

`requirements.txt` 固定 Python 3.11 搭配 Streamlit 1.56.0、MediaPipe 0.10.21、Protobuf 4.25.9、NumPy 1.26.4 及 OpenCV 4.11。請勿直接升級單一套件造成先前的相依衝突。MP4 建議 H.264 編碼、720p 或更小，每支影片盡量短；先用 3 段各 10–20 秒測試，不要一開始就上傳極大影片。

## 2. 第一次測試：只做第18張或任一影格
1. 上傳同一次動作的 `Left`、`Front`、`Right` 三支影片。為了核對鏡像，請先使用未鏡像版本。
2. 在「同步校正」填寫三鏡頭偏移。**鏡頭讀取時間＝參考時間＋偏移秒數**。例如參考畫面 5.0 秒，另一鏡頭要在 5.3 秒才是同一動作，就在該鏡頭填 `+0.30`。
3. 在「參考時間」選擇想測的一秒，按「預覽三視角同步畫面」，確認三圖的動作真的一致；不同步就改偏移，直到對上。
4. 選「單一時間點」→「執行跨視角角度比較」。
5. 在「三視角骨架檢視」選左／右人體側別，逐一檢查 **同一側** 耳、肩、肘、腕、髖的落點；尤其檢查被身體遮住的手臂有沒有被模型推錯。
6. 到「角度與視角建議」看各鏡頭角度、合格狀態、來源與警告；如果原側面不可用而另一視角適合，可能看到「研究候選：跨鏡頭」，**這只是待人工驗證的替代角度，不代表已自動修正正式 RULA**。
7. 到「人工角度 MAE」輸入人工角度，**另填正式 `222.py` 匯出的系統原始角度**，並在畫面選擇人工量的是「肘內角」還是「屈曲代理角」，才能算成對 MAE。若尚未填入正式原始角度，MAE 維持空白，不會偷用 Lab 重算值冒充正式基準。
8. 按「下載研究結果 ZIP」，保留全部候選角度與原始來源。

## 3. 正式做你已有的 30 筆人工角度比較
先用系統原本的抽樣時間（秒），不要只填照片編號：同一編號在 25 張和 30 張抽樣間對應的時間可能不同。從網頁下載 CSV 範本，**每筆人體側別一列**，格式如下：

| sample_id | time_sec | body_side | manual_forearm_deg | manual_neck_deg | baseline_forearm_deg | baseline_neck_deg |
|---|---:|---|---:|---:|---:|---:|
| 18 | 9.40 | 左手側 | 100 | 30 | 45.9 | 26 |
| 18 | 9.40 | 右手側 |  |  |  |  |

表中的第18張 `9.40` 秒與頸部角度**全部只是範例**，**不是你的實際資料**。請以原影片的實際時間戳和人工評分表為準。只有人工角度存在的那 30 筆才會納入人工角度比較；其餘 RULA 分數資料應另外保留，不要補 0 度。匯入 CSV 時表格欄位名稱要與範本一致，或使用有限的中文欄位別名。

最後請至少報告：① 原系統 MAE ② Lab 候選 MAE ③ 完整配對樣本數 ④ 視角可用率／不能選的筆數 ⑤ 各部位改善與惡化案例。**兩種 MAE 必須用同一批可比樣本計算**，不能只保留易辨識樣本就宣稱新法較準。

## 4. 程式有做／沒有做什麼？
**已實作**：兩種頸部參考線的診斷比較（v11.4 同側耳－肩－髖、舊版眼耳＋軀幹中心線；舊版不自動替換正式分數）；三影片同步偏移、鏡像輸入選項、指定人體左右側的 2D 角度、可見度與幾何品質篩選、原側面與其他鏡頭的候選比較、前臂投影長度的跨鏡頭啟發式篩選、保守視角建議、三鏡頭骨架顯示、CSV 人工輸入及成對 MAE、CSV/ZIP 匯出。

**尚未實作／尚未驗證**：相機標定與 3D 三角定位、實際頸椎角度真值、頭部完整 yaw/pitch 測量、跨鏡頭的已校正精準角度融合、每一類關節的可靠投影適用性分類、人工專家黃金標準、完整 RULA Table A/B/C 更新、逐影格時間暴露估計、從 CSV 直接回寫正式主程式。

**重要限制**：MediaPipe visibility 不是角度準確機率；肩線幾何／投影長度也是未經驗證的品質代理。與人工差異 20–30° 也可能來自量角基準不同、遮擋或模型關鍵點誤差，不能全歸因於離平面。對於同一人同一時間的多張影格，不可當作多個獨立受測者來報告外部效度。

## 5. 本機執行與測試
```bash
python -m venv .venv
# 啟用虛擬環境後：
pip install -r requirements.txt
streamlit run app.py
```

測試純演算法（需 `pytest`，不依賴 MediaPipe 與 Streamlit）：
```bash
pip install pytest
pytest -q tests/
```

## 6. 檔案用途
- `app.py`: Streamlit 操作介面與同時間抽樣推論。
- `angle_lab_core.py`: 同側人體關鍵點角度、幾何品質及跨視角候選決策。
- `requirements.txt`: 固定的部署版本。
- `packages.txt`: OpenCV 可能需要的 Linux 動態庫。
- `.streamlit/config.toml`: 外觀及單檔上傳大小限制。
- `tests/`: 純邏輯單元測試。
- `sample_angle_input_template.csv`: 研究資料欄位範本（示範時間，不是實際個案）。

最後建議：保持正式 RULA 系統不變；先測第18張，再跑你30筆有人工角度的資料；新法在**未參與調參**的影格上同樣改善，才有研究意義。

## 7. 特別注意：第18張人工100°可能與原系統45.9°是不同定義
你手繪的 `100°` 很可能是**肘內角**，而正式主系統前臂欄是 `180° - 肘內角` 的屈曲代理角。若是這樣，人工100°應先換成80°，再與原系統45.9°比較，不可直接以54.1°當作模型誤差。此轉換本身仍無法消除離平面投影誤差；必須先確認你的30筆人工角度是否都採一致的量角定義。網站預設「定義未確認」時會暫停前臂MAE，避免生成誤導性結果。
